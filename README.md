# ضيف — مساعد النزلاء الذكي لفنادق الحرمين

منصة SaaS تُشغّل مساعد واتساب لفنادق مكة والمدينة، مبنية خصيصًا للحاج والمعتمر.
المساعد **لا يجيب إلا من معلومات الفندق الموثّقة**، ويحوّل ما عداها إلى موظف بشري.

> مساعد ضيّق دائمًا صحيح، أثمن للفندق من مساعد واسع أحيانًا مخطئ.

📄 الفكرة وتحليل السوق والمنافسين وخارطة الطريق: [`docs/PRODUCT.md`](docs/PRODUCT.md)
💼 خطة العمل والتسعير وطريقة الوصول للعملاء: [`docs/BUSINESS.md`](docs/BUSINESS.md)
🚀 النشر على Railway: [`docs/DEPLOY.md`](docs/DEPLOY.md)
🔌 ربط نظام إدارة الفندق: [`docs/PMS_API.md`](docs/PMS_API.md)

## ما الذي يميّزه

| | الأدوات العامة | ضيف |
|---|---|---|
| مصدر الجواب | نموذج + مستندات | **حقيقة موثّقة بمعرّف، يتحقق منها الكود** |
| وقت الصلاة، فتوى، تصريح روضة | يجتهد | **يرفض ويحوّل — تسع فئات مطبّقة برمجيًا** |
| رمضان والحج | إعداد يدوي | **قاعدة المعرفة تنقلب بالموسم تلقائيًا** |
| لغة النزيل | ترجمة عامة | **عشر لغات، والتذكرة تصل للعمليات بالعربية** |
| لوحة الموظفين | إنجليزية | **ست لغات — عامل التدبير يقرأ التذكرة بلغته** |
| الغرفة | من نص الرسالة | **من سجل النزيل الموثّق فقط** |
| المطوّف | نزيل كأي نزيل | **طلب واحد يفتح تذكرة لكل غرفة في مجموعته** |

## التشغيل السريع

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

cp .env.example .env        # ثم عبّئ المفاتيح
export $(grep -v '^#' .env | xargs)

python -m daif.cli init
python -m daif.cli create-hotel taibah "فندق طيبة" --phone-number-id "<PHONE_NUMBER_ID>"
python -m daif.cli create-user taibah manager@taibah.sa --name "مدير الفندق" --role owner
python -m daif.cli import-kb taibah data/knowledge_base.yaml
python -m daif.cli serve --reload
```

اللوحة على <http://127.0.0.1:8000> و webhook واتساب على `/webhook/whatsapp`.

### ربط واتساب

1. في لوحة Meta for Developers، أضف منتج WhatsApp واحصل على `phone_number_id`.
2. اضبط `WHATSAPP_VERIFY_TOKEN` و `WHATSAPP_APP_SECRET` في البيئة.
3. سجّل رابط الـ webhook: `https://<نطاقك>/webhook/whatsapp`، واشترك في حقل `messages`.
4. من صفحة الإعدادات في اللوحة، أدخل `phone_number_id` ورمز الوصول للفندق.

> **ملاحظة اقتصادية:** الرد على رسالة نزيل خلال ٢٤ ساعة رسالة خدمة مجانية على واتساب.
> التكلفة الحقيقية توكِنات النموذج، ويخفّضها التخزين المؤقت للبرومبت.

### لماذا الحواجز في الكود لا في البرومبت فقط؟

البرومبت يوجّه النموذج ولا يضمنه. ما يعني خسارة حقيقية للفندق مطبّق مرتين:

| القاعدة | التطبيق البرمجي |
|---|---|
| لا جواب بلا مصدر | تُطابق المعرّفات مع قاعدة المعرفة؛ معرّف مخترع = تحويل |
| ثقة < ٠٫٧ | تحويل إجباري |
| الغرفة الموثّقة فقط | تذكرة لغرفة تخالف سجل النزيل تُلغى |
| الشكوى تصعد للمدير | إلغاء التذكرة وتحويل لمدير الوردية |
| موضوع ممنوع | تحويل حتى لو أجاب النموذج بثقة ٠٫٩٩ |
| وقت خارج نافذة التدبير | يُلغى الوقت المطلوب |
| ثلاث جمل كحد أقصى | يُقصّ الرد |

**الحواجز تشدّد فقط.** لا مسار واحد فيها يحوّل تحويلًا إلى جواب.

### وضع المطوّف

المواصفة تقبل طلبًا يغطي عدة غرف إذا ذكرها المطوّف صراحةً، وعقد المخرجات فيها
يحمل غرفة واحدة. الحل: حقل `rooms` اختياري (فارغ في الوضع الفردي، فلا يغيّر
العقد الأصلي)، وملحق برومبت يُضاف في وضع المطوّف وحده. كل غرفة تُطابَق مع
**قائمة غرف مجموعته المسجّلة في الفندق** — لا مع ما كتبه في الرسالة. طلب واحد
يفتح تذكرة مستقلة لكل غرفة، ليتابعها التدبير الفندقي غرفةً غرفة.

### المواسم تُجدوَل ولا تُبدَّل يدويًا

التبديل اليدوي يُنسى في ليلة الثلاثين من شعبان. المدير يُدخل تواريخ رمضان والحج
مرة واحدة، والنظام يبدّل من تلقاء نفسه — وخارج النوافذ يعود إلى `normal` لا إلى
آخر موسم يدوي، لأن بقاء وضع رمضان بعد العيد أخطر من العودة للوضع العادي.

### التصعيد

طلب عاجل حين يكون الاستقبال غير مشغّل يُنادي قناة الفندق المسجّلة (webhook)
بحمولة مختصرة يقرأها المناوب من إشعار جواله. فشل التصعيد يُسجَّل بوضوح ولا
يُسقط الرد على النزيل — فالرد أُرسل أصلًا.

### الموسم يعمل بالحذف لا بالتعليمات

في رمضان، حقيقة الإفطار العادي **لا تُعرض على النموذج أصلًا**. لا يستطيع اقتباس
ما لا يراه. وإن لم توجد حقيقة رمضانية بديلة، لا يجد مصدرًا فيحوّل.

| الصفحة | الغرض |
|---|---|
| نظرة عامة | نسبة الأتمتة، التحويلات، التذاكر، لغات النزلاء، توفير التخزين المؤقت، الحقائق المنتهية |

## الأمن

| الحاجز | التطبيق |
|---|---|
| CSRF | رمز إرسال مزدوج على كل نموذج؛ الـwebhook مستثنى وله توقيع Meta |
| أسرار مخزَّنة | رموز واتساب مشفَّرة في القاعدة، بمفتاح مشتقّ من `DAIF_SECRET_KEY` |
| الأدوار | ثلاثة أدوار متداخلة؛ القائمة تُخفي ما لا يملكه الدور، والمسار يرفضه |
| تحديد المعدّل | الدخول (بالعنوان والبريد معًا) والـwebhook |
| ترويسات | `nosniff`, `DENY`, `same-origin`, سياسة محتوى، و`HSTS` على https |
| عزل اللوحتين | كوكي وملح توقيع مختلفان — توقيع إحداهما لا يصلح للأخرى |

## الفوترة

أربع باقات (تجربة، ٩٩٩، ٢٤٩٩، ٦٩٩٩ ريال)، وعدّاد استهلاك شهري، وفواتير
بضريبة القيمة المضافة ١٥٪ ورمز ZATCA بصيغة TLV.

**قرار منتج:** تجاوز الحصة يُفوتر ولا يوقف المساعد. إيقافه في ذروة الموسم
يعني حاجًا مسنًا بلا جواب — ضرر أكبر من أي تأخّر في التحصيل.

## لوحة المنصة

على `/platform`، لمشغّل المنصة لا لموظفي الفنادق: الإيراد الشهري المتكرر،
المشتركون، تهيئة فندق جديد في خطوة واحدة (بقاعدة معرفة نموذجية تُنشأ معطّلة
حتى يراجعها المدير)، تغيير الباقات، وإصدار فواتير الشهر دفعةً واحدة.

```bash
python -m daif.cli create-admin ops@example.sa --name "مشغّل"
python -m daif.cli invoices --period 2026-09
```

## ربط نظام إدارة الفندق

المساعد ما يفتح تذكرة إلا لغرفة موثّقة. بدون ربط، الاستقبال يدخل رقم كل
نزيل يدويًا — وهذا أكبر احتكاك في التشغيل.

مع الربط (جرس، فندقة، Hotelogix، أو نظام داخلي): الغرفة تجي مع تسجيل
الوصول وتنفكّ مع المغادرة، بلا لمسة بشرية.

```bash
curl -X POST https://<نطاقك>/api/v1/guests/check-in \
  -H "Authorization: Bearer daif_xxxxxxxx_..." \
  -H "Content-Type: application/json" \
  -d '{"wa_id":"966500000001","room":"402","name":"أحمد"}'
```

المفاتيح من **الإعدادات ← مفاتيح الربط** (المالك بس). التفاصيل في
[`docs/PMS_API.md`](docs/PMS_API.md).

## النشر

**Railway** — الرفع كله من الواجهة، بلا طرفية: [`docs/DEPLOY.md`](docs/DEPLOY.md)

**Docker** في أي مكان ثاني:

```bash
cp .env.example .env      # واضبط DAIF_SECRET_KEY و DAIF_DASHBOARD_SECRET
docker compose up --build
```

الترحيلات تُطبَّق تلقائيًا عند الإقلاع (`alembic upgrade head`).
نقاط الفحص: `/healthz` (العملية حية) و`/readyz` (قاعدة البيانات تستجيب).

## الاختبارات

```bash
pytest -q
```

٢١٥ اختبارًا تغطي: الحواجز، كشف المواضيع الممنوعة (دقة واسترجاع عبر اللغات)،
فلترة الموسم والصلاحية، جدولة المواسم، تركيب البرومبت والتخزين المؤقت، وضع
المطوّف وصلاحيات الغرف، تحقق توقيع واتساب، التصعيد، التشفير والأدوار وتحديد
المعدّل، الحصص والضريبة ورمز ZATCA، التصدير وتقرير الوردية، التدفق الكامل،
مفاتيح الربط وواجهة الـPMS، **وعزل البيانات بين الفنادق وبين اللوحتين
وبين مفاتيح الربط**، وأمثلة المواصفة الثمانية كاختبار انحدار.

## متغيرات البيئة

انظر [`.env.example`](.env.example). الأساسية:

| المتغير | الغرض |
|---|---|
| `ANTHROPIC_API_KEY` | مفتاح Claude |
| `DAIF_MODEL` | افتراضيًا `claude-opus-5` |
| `DAIF_CONFIDENCE_THRESHOLD` | عتبة التحويل، افتراضيًا `0.7` |
| `DAIF_DATABASE_URL` | SQLite افتراضيًا، ويقبل Postgres |
| `WHATSAPP_VERIFY_TOKEN` | تحقق اشتراك webhook |
| `WHATSAPP_APP_SECRET` | تحقق توقيع الحمولة — **بدونه تُرفض كل الطلبات** |
| `DAIF_DASHBOARD_SECRET` | توقيع جلسات اللوحتين |
| `DAIF_SECRET_KEY` | تشفير الأسرار — **بدونه يُرفض تخزين رمز واتساب** |
